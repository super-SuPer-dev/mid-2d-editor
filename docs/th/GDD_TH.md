# Low Altitude Warrior — เอกสารออกแบบเกมฉบับภาษาไทย

**เวอร์ชัน:** 2.0  
**สถานะ:** ข้อกำหนดการออกแบบสำหรับการผลิต  
**เอกสารหลัก:** [Game Design Document ภาษาอังกฤษ](../../Game%20Design%20Document.md) เป็นฉบับอ้างอิงสูงสุด หากข้อความต่างกันให้ยึดภาษาอังกฤษ  
**ภาษาในเกม:** อังกฤษเป็นค่าเริ่มต้น ภาษาไทยเป็นตัวเลือกที่สมบูรณ์

## 1. แนวคิดหลัก

*Low Altitude Warrior* เป็นเกมแอ็กชันแพลตฟอร์มมุมมองด้านข้างแนวไซไฟชนบทไทย ผู้เล่นรับบทเจ้าหน้าที่ภาคสนามของ ACO ใช้เครื่องตัดหญ้าแบบสะพายหลังที่ดัดแปลงเป็นอาวุธ ต่อสู้กับระบบนิเวศต่างดาวที่ดูดซับและนำพันธุกรรมผลไม้ที่ปลูกในไทยมาเป็นอาวุธ ติดตามเครือข่ายรากผ่านห้าพื้นที่ และหยุด Capsule 07 ก่อนการงอกระดับดาวเคราะห์

โลก เนื้อเรื่อง และอุปกรณ์ต้องให้ความรู้สึกเป็นภาคอีสานร่วมสมัยโดยไม่ทำให้เป็นภาพล้อเลียน เทคโนโลยีภาคสนามที่ซ่อมและดัดแปลงจากของใกล้ตัวต้องอยู่ร่วมกับชีววิทยาต่างดาวที่รุกรานอย่างน่าเชื่อถือ `[GDD-VISION-01]`

### 1.1 คำมั่นต่อผู้เล่น

- การเคลื่อนที่ กระโดด แดช และฟันที่ตอบสนองทันที
- การต่อสู้ด้วยใบตัดที่อ่านจังหวะได้และมีแรงปะทะชัดเจน
- พื้นที่ชนบทห้าแบบที่มีเดิมพันทางนิเวศเพิ่มขึ้นเรื่อย ๆ
- ความก้าวหน้าถาวรระหว่างภารกิจโดยไม่ต้องบริหารระบบซับซ้อน

### 1.2 ประเภทและกล้อง

เกมเป็น side-scrolling action-platformer พร้อม light RPG progression สำหรับ Windows และ Web การออกแบบแบบ top-down ในเอกสารเก่าถูกยกเลิก ฉาก การชน การเคลื่อนที่ และการต่อสู้ด้านข้างที่ใช้งานจริงคือมาตรฐาน

### 1.3 ลำดับแรงบันดาลใจ

[GDD-INSPIRATION-01] **Hollow Knight และ Castlevania เป็นแรงบันดาลใจหลักด้าน gameplay และ presentation** ใช้เป็นมาตรฐานสำหรับการเคลื่อนที่ด้านข้างที่ตอบสนองแม่นยำ, ระยะประชิดที่จงใจ, การวางศัตรูที่มีหน้าที่, ฉากหลายชั้นมีบรรยากาศ, set piece ระดับห้อง และบอสที่ให้ผู้เล่นอ่าน telegraph ก่อนลงมือ

- **Hollow Knight:** ความแม่นของ movement/attack, silhouette สะอาด, combat UI ที่ไม่รบกวน, mood ของฉาก และ phase บอสที่เรียนรู้เป็นจังหวะได้
- **Castlevania:** การจัด platform ร่วมกับศัตรู, biome/landmark ที่ไต่ระดับชัด, การเปิดตัวสัตว์ประหลาด, วิถีกระสุนอ่านง่าย และ encounter ที่ทวีความเข้มข้นโดยดัดแปลงเข้าชนบทไทย
- **Touhou:** เป็นแรงบันดาลใจรองเฉพาะ formation, rhythm และ safe-lane logic ของกระสุนในบอสบาง phase ไม่ได้กำหนดโครงสร้างแคมเปญ ความหนาแน่น combat ปกติ visual style หรือระดับความยากรวม

แรงบันดาลใจเหล่านี้กำหนดคุณภาพและความรู้สึก ไม่ใช่ให้ลอก content เกมยังเป็นแคมเปญเส้นตรงห้าภารกิจ ไม่ใช่โลก Metroidvania เชื่อมต่อกัน และ map, character, creature, UI, music, animation silhouette และ attack pattern ต้องเป็นงานต้นฉบับของ ACO และไซไฟไทย

## 2. ขอบเขตผลิตภัณฑ์

กลุ่มเป้าหมายคือผู้เล่นแอ็กชันอินดี้ที่ชอบภารกิจสั้น ระบบอ่านง่าย กลิ่นอายไทย และการพัฒนาตัวละครแบบกระชับ รองรับคีย์บอร์ดและเมาส์เป็นหลัก

แต่ละภารกิจยาวเป้าหมาย **5–7 นาที** ตั้งแต่เริ่มควบคุมจนถอนกำลัง แคมเปญครั้งแรกประมาณ 35–50 นาทีรวมเมนูและ retry ตามปกติ ใช้ระดับความยากหลักหนึ่งระดับตอนเปิดตัว และมีภารกิจห้าด่าน บอสเฉพาะห้าตัว ศัตรูมาตรฐานหกตระกูล เจ้าหน้าที่สี่คน เนื้อเรื่องเส้นตรง และตอนจบหนึ่งแบบ

สิ่งที่ไม่รวม: multiplayer, online ranking, branching quest, หลายสกุลเงิน, ฐานที่เดินสำรวจได้, moveset เฉพาะตัวเต็มรูปแบบ และเสียงพากย์ `[GDD-SCOPE-01]`

## 3. เสาหลักการออกแบบ

1. **อุปกรณ์ภาคสนามไทยปะทะชีววิทยาต่างดาวจากผลไม้** — เครื่องมือท้องถิ่น การแก้ปัญหาหน้างาน และกายวิภาคผลไม้ไทยต้องยังอ่านออกภายใต้การกลายพันธุ์ `[GDD-PILLAR-01]`
2. **การต่อสู้ด้วยเครื่องตัดที่อ่านง่าย** — ทุกการโจมตีมีการเตรียม จังหวะโดน และการฟื้นตัวที่สื่อสารชัด `[GDD-PILLAR-02]`
3. **ชนบทแต่ละพื้นที่มีเอกลักษณ์และเดิมพันทางนิเวศ** — ภาพ ศัตรู อันตราย และเรื่องเล่าของแต่ละไบโอมต้องแตกต่าง `[GDD-PILLAR-03]`
4. **ความก้าวหน้าถาวรที่กระชับ** — การอัปเกรดช่วยให้เลือกแนวทางได้โดยไม่สร้างเมนูหรือสกุลเงินเกินจำเป็น `[GDD-PILLAR-04]`

## 4. วงจรหลัก

`เลือกเจ้าหน้าที่ → รับฟังสรุปภารกิจ → กำจัดภัยคุกคามตามโควตา → ปราบบอส → ถอนกำลัง → สรุปผล → อัปเกรด`

ทุกภารกิจใช้สถานะเรียงลำดับ `[GDD-LOOP-01]`:

1. `CLEAR_THREATS` — เปิดพื้นที่ เก็บตัวอย่าง และกำจัดศัตรูให้ครบโควตา
2. `BOSS_ACTIVE` — ล็อกเงื่อนไขถอนกำลัง เปิดบอสและ HUD บอส
3. `EXTRACTION` — หลังบอสแพ้จึงเปิดจุดถอนกำลังและจบภารกิจได้

ฐาน ACO แสดงผ่านเมนู เลือกตัวละคร อัปเกรด สรุปภารกิจ การสื่อสาร NPC และผลภารกิจ ไม่มีฉากฐานที่เดินสำรวจ

### 4.1 สัญญาจังหวะด่าน

Critical path ของทุกด่านใช้เวลา 5–7 นาที ไม่รวม briefing/debriefing `[GDD-LEVEL-01]`: เปิดด่านและสอนกลไก 30–45 วินาที, encounter A 60–90 วินาที, traversal set piece 60–90 วินาที, encounter B/ทางเข้าบอส 60–90 วินาที, บอส 75–120 วินาที และถอนกำลัง 15–30 วินาที

ทุกด่านมี gameplay beat ที่ออกแบบไว้สามช่วงก่อนบอส ห้ามยืดเวลาโดยทำ corridor ซ้ำหรือเพิ่ม HP อย่างเดียว เส้นทางตัวอย่างเสริมเพิ่มเวลา critical path ได้ไม่เกิน 45 วินาที และบอสวัดการเรียนรู้ pattern มากกว่าการเป็น damage sponge

## 5. การควบคุมและกติกาผู้เล่น

- เคลื่อนซ้าย/ขวา กระโดด แดช โจมตี หยุดเกม และโต้ตอบ UI
- แดชต้องมี cooldown ที่อ่านได้และไม่กลบสถานะ hurt/death
- การโจมตีมี anticipation/contact/recovery และพื้นที่โจมตีตรงกับภาพ
- ความเสียหายทุกแหล่งมี feedback; ผู้เล่นมีช่วงคุ้มกันสั้นหลังโดน
- เส้นทางหลักทุกเส้นต้องผ่านได้ด้วยเจ้าหน้าที่ที่ช้าที่สุดก่อนอัปเกรด
- ความล้มเหลวเริ่มภารกิจใหม่โดยไม่ทำลาย campaign progress

ความรู้สึกของการตัดและความชัดเจนของ hitbox สำคัญกว่าความเร็วของเอฟเฟกต์ `[GDD-COMBAT-01]`

## 6. เจ้าหน้าที่

เจ้าหน้าที่ทั้งสี่ใช้ input และ animation contract เดียวกัน ค่าสถานะพื้นฐานที่ใช้งานอยู่ยังคงเป็นจุดเริ่มในการบาลานซ์ แต่ความแตกต่างหลักมาจาก passive หนึ่งอย่าง

| ID | ชื่อ | บุคลิก/บทบาท | Passive |
|---|---|---|---|
| `tonkla` | Tonkla / ต้นกล้า | เจ้าหน้าที่ภาคสนามผู้ยืดหยุ่น | เก็บตัวอย่างครบ 3 ชิ้น ฟื้น 1 HP |
| `rin` | Rin / ริน | หน่วยสอดแนมที่แม่นยำ | dash cooldown ลด 25% |
| `khem` | Khem / เข้ม | ผู้เชี่ยวชาญงานหนัก | พื้นที่โจมตีใบตัดเพิ่ม 25% |
| `t800` | T-800 | แพลตฟอร์มกักกันจักรกล | ลดความเสียหายที่ได้รับ 1 แต่ความเสียหายขั้นต่ำ 1 |

ค่าตัวเลขทั้งหมดเป็น data-driven และปรับได้โดยไม่แก้ฉาก `[GDD-OPERATOR-01]`

น้ำเสียงเจ้าหน้าที่: Tonkla จริงใจและมองโลกเชิงปฏิบัติ, Rin สั้นและสังเกตเก่ง, Khem มั่นใจแต่ไม่ประมาท, T-800 ใช้ภาษาระบบแห้ง ๆ เจ้าหน้าที่ตอบเฉพาะจังหวะสำคัญ ไม่พูดทับข้อมูลบอสหรือชัยชนะ `[GDD-NARRATIVE-07]`

## 7. ความก้าวหน้าและเศรษฐกิจ

ตัวอย่างชีวภาพเป็นสกุลเงินเดียว ได้จากการเก็บและผลภารกิจ สำเร็จภารกิจจึงนำตัวอย่างของรอบนั้นกลับฐาน; ความล้มเหลวไม่ฝากตัวอย่างใหม่ `[GDD-ECONOMY-01]`

**Base Technology** ใช้ร่วมกันทุกเจ้าหน้าที่ ระดับ 0–5:

- Blade — ความเสียหาย/ประสิทธิภาพการตัด
- Engine — การเคลื่อนที่ แดช หรือความคล่องตัวตามสูตรที่อนุมัติ
- Armor — HP/ความทนทานตามสูตรที่อนุมัติ

**Operator Mastery** แยก rank 0–5 ต่อเจ้าหน้าที่ ค่าใช้จ่ายพื้นฐาน `3 + rank × 3` ตัวอย่าง ช่วยพัฒนา passive และให้โบนัส milestone แทร็ก Blade/Engine/Armor ที่ซ้ำในแต่ละตัวละครต้องถูกยกเลิกผ่าน save migration v2 `[GDD-PROGRESSION-01]`

## 8. ศัตรูและบอส

ศัตรูมาตรฐานหกตระกูล:

- `thornling` หน่วยประชิดพื้นฐาน
- `spitter` ยิงกระสุนและควบคุมพื้นที่
- `maw` ประชิดแรงพร้อมจังหวะเตรียมชัด
- `capsule_husk` เกราะเปิด weak core หลังพุ่งควบคุมเลน เริ่มในด่าน 3
- `root_skitter` มุดดินและโจมตีจากเส้นทางพื้น
- `eye_wisp` ภัยคุกคามบิน/พลังงานในช่วงท้าย

แต่ละตระกูลต้องมี silhouette, telegraph, timing และบทบาทต่างกัน ไม่ใช่เพียงย้อมสีหรือขยาย placeholder `[GDD-ENEMY-01]`

ผลไม้ท้องถิ่นไทย—ในที่นี้หมายถึงผลไม้ที่ปลูกในประเทศไทยและคุ้นเคยผ่านสวน ตลาด อาหาร และวัฒนธรรมภูมิภาค—เป็นธีมหลักอย่างเป็นทางการของศัตรูอินทรีย์และบอสทั้งหมด เอกลักษณ์ผลไม้ต้องกำหนด silhouette, พื้นผิว, การเคลื่อนที่, ภาษาการโจมตี, กระสุน และ hazard ไม่ใช่เป็นเพียงของตกแต่ง Capsule 07 ยึดพันธุกรรมผลไม้ในพื้นที่แล้วเปลี่ยนเปลือก เมล็ด เนื้อ กลีบเลี้ยง พวง ยาง เส้นใย และรากให้เป็นเกราะ อวัยวะรับรู้ และอาวุธ ราก เถาวัลย์ เห็ดรา และเนื้อเยื่อ capsule ใช้เป็นชีววิทยาเชื่อมรองได้ แต่ห้ามแทนผลไม้หลักในการอ่านตัวศัตรู `[GDD-FRUIT-01]` การอ่านการต่อสู้สำคัญกว่าความเหมือนผลไม้ แต่ละตระกูลต้องมีผลไม้อ้างอิงหลักเพียงหนึ่งชนิด silhouette และกลไกเฉพาะ ห้ามทำเป็นมาสคอตผลไม้น่ารักหรือใช้ทรงกลมเดิมแล้วย้อมสี

concept sheet ของศัตรูทุกตระกูลต้องระบุผลไม้หลักและแสดงการแปลงโครงสร้างที่จำได้อย่างน้อย 3 อย่าง เช่น เปลือก เมล็ด เนื้อ กลีบเลี้ยง พวง ยาง เส้นใย หรือราก ไปเป็นกายวิภาค telegraph การป้องกัน การเคลื่อนที่ หรือการโจมตี และอย่างน้อย 1 อย่างต้องมีผลต่อ gameplay งานพืชต่างดาวทั่วไปที่เพียงใช้สีผลไม้หรือนำผลไม้มาติดบนตัวไม่ผ่าน theme review ศัตรูมาตรฐานในด่านเดียวกันต้องใช้ผลไม้หลักต่างชนิดกัน บอสผสมได้ไม่เกิน 2 ผลไม้และต้องมีหนึ่งชนิดที่อ่านเด่นชัดในขนาด gameplay เพื่อไม่ให้รายละเอียดรกจนอ่านไม่ออก

| ศัตรู | ผลไม้อ้างอิง | ภาษาการกลายพันธุ์ |
|---|---|---|
| Thornling | เงาะ | ขนเปลือกเป็นหนามพุ่งและเกราะสัมผัส |
| Spitter | มะกรูด | ผิวขรุขระพองก่อนยิงถุงเมล็ด/สปอร์กรด |
| Maw | มังคุดอ่อน | เปลือกเขียว-ม่วงหนาแยกเป็นกรามรอบแกนเป็นพู |
| Capsule Husk | กระท้อน | เปลือกหนาและเนื้อเป็นพูเปิดเผย weak seed core |
| Root Skitter | สละ | เกล็ดเปลือกและรากปาล์มเป็นตัวมุดดินทรงเตี้ย |
| Eye Wisp | ลำไย | เนื้อซีดและเมล็ดดำเป็นดวงตาในพวงลอยได้ |

บอสยกระดับภาษาเดียวกัน: Thorn Matriarch เป็นพวงราชินีเงาะ, Maw Sovereign ใช้มงกุฎทุเรียนบนกายมังคุด, Possessed Banyan ใช้ขนุนผสานลูกไทร, Root Hydra ใช้พวงลูกจาก และ Root-Core Eye ใช้พวงตาลำไยในกลีบแก้วมังกร ด่าน 1–5 จึงไล่จาก เงาะ/มะกรูด → มังคุด/ทุเรียน → กระท้อน/ขนุน → สละ/ลูกจาก → ลำไย/แก้วมังกร แอนิเมชันที่อนุมัติแล้วให้เติมรายละเอียดผลไม้เฉพาะจุดก่อนพิจารณาทิ้งใหม่ทั้งหมด

ทุกด่านมีบอสเฉพาะตัว บอสต้องมี lifecycle, phase, health และ defeat signal มาตรฐาน มีอย่างน้อยสองรูปแบบการโจมตี การเปลี่ยนเฟสที่อ่านได้ และ death sequence ที่ชัด ความเสียหายสำคัญต้องมี telegraph ก่อน hitbox ทำงาน `[GDD-BOSS-01]`

พื้นฐานบอสยึด Hollow Knight/Castlevania: ระยะประชิดชัด, anticipation อ่านได้, การโจมตีมี commitment และ punish window บาง phase จึงเสริม **Touhou-inspired danmaku ที่ปรับให้อ่านง่ายใน platformer** `[GDD-BULLET-01]` ได้แก่ fan, aimed burst, rotating ring, alternating lane wall, arc และ spiral ทุก pattern ต้องมี ID, telegraph, ช่วง active, recovery, speed band, projectile cap และ cleanup ที่ deterministic ทางปลอดภัยกว้างอย่างน้อย 1.75 เท่าตัวผู้เล่นและต้องใช้ได้จริงเมื่อกระโดด/ตก/แดช ห้ามเกิดกระสุนในตัวผู้เล่นหรือยิงจากนอกกล้องโดยไม่มีสัญญาณ

ช่วงกระสุนหนาแน่นยาว 3–6 วินาทีและมีช่วงผ่อนแรงหรือ punish window อย่างน้อย 0.75 วินาที cap แนะนำคือด่าน 1/2/3/4/5 เท่ากับ 18/32/36/48/64 นัด กระสุนต้องหายเมื่อเปลี่ยน phase บอสตาย retry หรือออก arena และ Web ลดได้เฉพาะกระสุนตกแต่ง ห้ามทำลายตรรกะ safe lane

## 13. ทิศทางศิลป์

ใช้แนว **high-resolution pixel art**: รูปทรงตั้งใจให้เรียบง่ายและสร้างด้วยกลุ่มพิกเซลสี่เหลี่ยมที่เห็นชัด แม้ไฟล์มีความละเอียดสูงก็ห้ามกลายเป็นภาพสมจริง ภาพวาดแบบ painterly หรือภาพเรนเดอร์ 3D ภาพทุกชิ้นต้องมี alpha, logical pixel grid, gutter, baseline, pivot และ filtering ที่เหมาะสม `[GDD-ART-01]`

sprite, portrait และฉากใช้ขอบคม, color ramp จำกัด, stepped curve และ integer nearest-neighbor scaling ห้าม soft airbrush, texture ผิวคนสมจริง, gradient ต่อเนื่อง, PBR material, depth of field และ anti-aliasing ที่ทำให้กลุ่มพิกเซลเบลอ Portrait ต้องลดทอนใบหน้าให้เป็น pixel cluster ที่อ่านง่ายและสอดคล้องกับ sprite ในเกม

แต่ละไบโอมมี palette/landmark ต่างกัน: ทุ่งปนเปื้อน, ป่ากลายพันธุ์, ห้องรากใต้แคปซูล, บึงรากกินกลืน และแกนตาต่างดาว VFX ห้ามกลบ telegraph หรือ hitbox

## 14. ทิศทางเสียง

ไม่มีเสียงพากย์ `[GDD-AUDIO-01]` ต้องมีเพลงเมนู/ฐาน 1 เพลง, level loop 5 เพลง, boss suite ใช้ซ้ำ 2 ชุด, victory/defeat stinger และ SFX ประมาณ 40 เสียง ครอบคลุมเจ้าหน้าที่ เครื่องตัด ศัตรู บอส pickup ฉาก radio และ UI สัญญาณโจมตีสำคัญต้องได้ยินเหนือเพลงและเครื่องตัด

## 15. เป้าหมายเทคนิคและประสิทธิภาพ

Godot รองรับ Windows และ Web เป้าหมาย 60 FPS ที่ 1280×720, Web memory ต่ำกว่า 512 MB, save schema v2, Unicode/ฟอนต์เทียบเท่ากัน และไม่มี soft-lock ระหว่าง phase/dialogue/retry `[GDD-TECH-01]`

LevelCatalog ในอนาคตเพิ่ม threat quota, boss ID/name key, biome, briefing/radio/debrief sequences และ mission phases CharacterCatalog เพิ่ม passive/mastery configuration ระบบ boss ส่ง lifecycle/phase/health signal ระบบ localization ใช้ `TranslationServer`

## 16. เกณฑ์ความสมบูรณ์

เกมออกแบบสมบูรณ์เมื่อ `[GDD-DONE-01]`:

- แคมเปญห้าด่าน บอสห้าตัว และสาม mission phases ทำงานครบ
- เจ้าหน้าที่สี่คนมี passive และ Mastery ที่ตรวจสอบแล้ว
- เนื้อเรื่อง การ skip/retry และ unlock ไม่ขัดแย้งกัน
- English/Thai ครบและ English เป็นค่าเริ่มต้น
- ไม่มี asset P0 ต่ำกว่า Verified และไม่มี P0/P1 defect
- readiness ตาม [Validation Protocol](VALIDATION_PROTOCOL_TH.md) อย่างน้อย 90%
- Windows/Web ผ่าน performance, memory, Unicode, save migration และ soak test
